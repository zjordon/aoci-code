# AOCI-CODE - 使用指南

> 生成时间: 2026-10-13
> 分析对象: github.com/aoci-spec/aoci-code @ v0.1.0-rc20

## 1. 这是什么、给谁用

**AOCI-CODE** 为 coding agent（Codex、Claude Code、Cursor、OpenCode、Qoder…）维护一份随项目入库、Git 版本化的认知索引（FRAS 格式，一行一个文件）。智能体开工前读一遍索引即知全系统：每个文件的职责、必读关联、对外契约、不可破坏的约束——不必每个任务都重读仓库。

- **适用**：约 50 万行以内的代码库（实际限制是索引体积而非行数；70 万行商业系统对应约 30 万 token 索引）；可选 MySQL / PostgreSQL / openGauss 表结构索引。
- **不适用**：期望"零成本集成"的场景——首次建索引约 20 万行/小时（取决于模型与宿主），且需要智能体配合分批完成。
- **许可**：FSL-1.1-MIT（Fair Source，源码可见；每个版本公开满两年后自动转 MIT）。

## 2. 安装

### 2.1 要求

| 项 | 要求 |
|----|------|
| 二进制 | 已验证的签名发布包，或规范源码仓的自构建产物 |
| 源码构建 | go.mod 声明的 Go 工具链（1.26.9，带完整补丁号）、`make` |
| 宿主 | 支持标准 stdio MCP 的智能体（Codex / Claude Code / Cursor / OpenCode V1 / Qoder） |
| 项目 | 目标仓库的正常读写权限；scan 需要 Git 工作树 |

AOCI 与 MCP 宿主集成，**不与模型厂商 API 集成**——DeepSeek 等模型只要宿主支持 stdio MCP 就能用。

### 2.2 路线 A：签名发布包（推荐）

```bash
gh auth login
gh release download v0.1.0-rc20 --repo aoci-spec/aoci-code
```

或浏览器匿名下载 Release 归档 + 校验资产。按 `docs/install.md` 的基础/推荐/完整三级验证（checksums → cosign 签名 → attestation → SBOM → manifest）确认后，把 `aoci`（Windows 为 `aoci.exe`）放到**稳定绝对路径**。

### 2.3 路线 B：源码构建

Linux/macOS：

```bash
git clone https://github.com/aoci-spec/aoci-code.git
cd aoci-code
mkdir -p build && make build
./build/aoci --version
```

Windows PowerShell：

```powershell
git clone https://github.com/aoci-spec/aoci-code.git
Set-Location .\aoci-code
New-Item -ItemType Directory -Force .\build | Out-Null
make build
.\build\aoci.exe --version
```

源码构建自报精确 checkout 版本（如 `v0.1.0-rc20-1-g<short>`），与签名包的 `0.1.0-rc20` 是不同构建输入，不是版本冲突。

## 3. 快速开始（推荐流程：交给智能体）

**第一步**——把下面这段发给你的智能体（它会下载、安装、初始化）：

```text
AOCI-CODE project: https://github.com/aoci-spec/aoci-code

Download the latest release package for this operating system and CPU architecture from
https://github.com/aoci-spec/aoci-code/releases, and follow the installation instructions
on the Release page to verify it. If no compatible release package exists, or if I
explicitly request the latest source, build it from the official repository.

After extracting the package, place aoci (aoci.exe on Windows) at a stable absolute path.
Then use that absolute path to do the following for my project:

1. Run init to initialize AOCI and integrate MCP for the current host; if this host does
   not write project configuration (Cursor, for example), give me the configuration I
   need to paste myself
2. Run scan

   scan takes its file inventory from Git, so do not add the cognition assets
   init writes (aoci.txt, aoci.meta.txt, aoci.code.txt, AGENTS.md) to .gitignore
   or .git/info/exclude — an ignored asset is silently skipped and the index
   cannot be built. Leave the host-config ignore init writes for itself as it is.

3. Tell me to restart the agent so the newly written MCP server takes effect

Stop after those three steps and do not build the index yet — I will tell you to continue
after the restart.
```

**第二步**——重启智能体后发送：

```text
First confirm the AOCI MCP server is connected, then build the AOCI index for this project.
When it is complete, give me the AOCI panel link.
```

智能体会后台启动面板（`aoci ui --detach --json`）并给你链接。

> **为什么要重启**：索引通过 AOCI 的 MCP 工具写入，而跑 `init` 的会话还没加载 `init` 刚写的 MCP 服务器配置。能动态加载 MCP 的宿主可能不需要重启。

### 3.1 手动初始化（等价路径）

```bash
AOCI=/absolute/path/to/aoci-code/build/aoci
"$AOCI" --repo . init --locale en-US --agent codex
"$AOCI" --repo . scan
```

Windows PowerShell：

```powershell
$Aoci = (Resolve-Path "C:\path\to\aoci-code\build\aoci.exe").Path
& $Aoci --repo . init --locale en-US --agent codex
& $Aoci --repo . scan
```

注意事项：

- `init` 写入 locale 配置、AGENTS.md 受管规则块、Git 边界与空索引骨架；**不从文件名/目录/AST 臆造业务含义**；
- 新仓库首次 `scan` 建立受管 Baseline；已有受管 Baseline 的项目增删范围要走正式 Scope Change 流程，`scan --force` 不是捷径，也抹不掉未解决的漂移/回执/恢复边界；
- **认知资产（aoci.*.txt、AGENTS.md）绝不能加入 .gitignore**——被忽略的资产会被 scan 静默跳过，索引建不起来。

### 3.2 建完索引后的验证

```bash
aoci --repo . verify --json   # 报告 Missing / Orphan / Stale / Unbaselined
aoci --repo . check --json    # 聚合治理门
aoci --repo . doctor          # 仓库与宿主集成诊断
```

### 3.3 会话被压缩后（context compaction）

给智能体发：

```text
Using only AOCI, establish whole-framework cognition of this project, tell me your mastery
of each area as a percentage, and whether you can take over development.
```

它会重新走一遍完整 Overview 投递（分块 + 游标 + 证明）。压缩后的交接只保留回执身份与重载指令，**不得**把索引内容复制进交接当可靠认知。

## 4. 常用 CLI 命令

| 命令 | 用途 |
|------|------|
| `aoci init` | 安装仓库契约与初始 Volumes 布局（无业务含义） |
| `aoci scan` | 首次集成建立 Baseline；既有 Baseline 下的范围变化进 Scope Change |
| `aoci status --deep` | Legacy 深度状态（非 Volumes 维护路径） |
| `aoci ui` / `--detach` / `--stop` | 回环只读面板：索引原文、覆盖与压缩比、分块计划、漂移、运行中服务器 |
| `aoci verify` | 报告 Missing / Orphan / Stale / Unbaselined |
| `aoci check` | 聚合治理门 |
| `aoci index agent guide` | 进入确定性的宿主-智能体工作流（Live Guide） |
| `aoci capabilities` | 当前二进制提供的能力 |
| `aoci doctor` | 诊断仓库与宿主集成 |
| `aoci database` | 配置/校验 PostgreSQL / MySQL / openGauss 证据 |
| `aoci database source access` | 只读检查外部环境是否提供了凭据引用（不回显凭据值） |
| `aoci database cognition bootstrap` | 给已对齐的 Code-only 项目加数据库认知 |
| `aoci cognition plan` | bootstrap / Legacy→Volumes 迁移计划的只读预览 |
| `aoci cognition system lineage/relations/impact/snapshot/evolution` | 派生的系统认知观察（血缘/关系/影响面/快照/演化） |
| `aoci mcp` | 启动 stdio MCP 服务器 |

```bash
# 常见组合
aoci --repo . init --locale en-US --agent codex
aoci --repo . scan
aoci --repo . verify --json && aoci --repo . check --json
aoci --repo . index agent guide --agent codex --json   # 不要在包装脚本里复刻状态机
aoci --repo . database source access --source primary --json
aoci --repo . mcp
```

> Plan / Stage / Check / Diff / Apply / Curation / Scope Change / Bootstrap / Migration 及恢复命令仍然存在，但**以运行中二进制返回的 Guide 为准**，不要把内部状态机抄进脚本。

**关于"只读"**：verify / check / index score / index inventory 的只读指不改正式索引与 Baseline；Ledger 启用时仍可能追加本地账本与 Verify History。需要严格零写入就用隔离副本。

## 5. MCP 服务器（九工具）

`aoci mcp` 无常驻守护进程，stdio 上恰好暴露九个工具：

| 类别 | 工具 |
|------|------|
| 读 | `aoci_rules`、`aoci_overview`、`aoci_get_entries`、`aoci_search` |
| 维护 | `aoci_maintain`、`aoci_update_entry`、`aoci_remove_entry` |
| 佐证 | `aoci_header`、`aoci_report` |

- MCP 模式下 stdout 保留给 JSON-RPC，日志与诊断走 stderr；
- **运行中二进制提供的工具描述、JSON schema 与机器状态值才是权威**，README/本文只是起点；
- Overview 分块投递：`overview_delivery.chunk_tokens` 默认 7000（4000–24000），超预算自动分块、跟随 `next_cursor`、单次证明提交；刷新阈值默认 30 个不同语义路径（可按项目配置）。

## 6. 索引长什么样

```text
atomic.go[CG9L]: F:Provides durable replace CAS, create CAS, atomic writes... | R:code:internal/fs/atomic_exchange_linux.go,... | A:AtomicWrite,AtomicWriteCAS,... | S:Native publication never degrades to an overwriting rename...
```

| 字段 | 含义 |
|------|------|
| `[CG9L]` | 层（C-Code）+ 模块（G-General）+ 重要性（9-core…1-edge）+ 规模（L>400 / M / S / T<100 行） |
| `F` | 该文件的职责 |
| `R` | 与它必须同读的文件 |
| `A` | 调用方依赖的公共契约 |
| `S` | 从代码推断不出、但绝不能错的事实（受配额约束：C9-8≤600 / C7-4≤200 / C3-1≤50） |

三卷布局：`aoci.txt`（根清单）→ `aoci.meta.txt`（字典与纪律）→ `aoci.code.txt`（条目）。

## 7. 数据库认知（可选）

```text
声明数据源（aoci database source…）→ 宿主环境提供连接串环境变量（AOCI 不存凭据）
→ aoci database evidence（目录级只读采集）→ 智能体证据绑定授权 → 表级 FRAS 条目
```

- 支持：PostgreSQL、MySQL 5.7.6+（**不支持 MariaDB**；CHECK 约束需 8.0.16+）、openGauss 6.0.5（verify-full TLS，仅 A/PG 基表）；
- 只读表结构（目录元数据），**永不读业务数据**；
- 先建代码索引，再加数据库索引；
- `aoci database source access` 只检查凭据引用是否存在，不回显值。

## 8. 日常任务怎么跑

- **开发任务中**：不需要每次请求都以"维护索引"结尾。项目规则（AGENTS.md 块）与 MCP 工作流会让智能体在受管对象变化时**顺手增量维护**——Maintain 检测漂移并签发待更新条目；
- **换人/换智能体/新会话**：索引随仓库走，读一遍即接续；
- **回滚**：索引是 Git 版本化的文本，随代码一起 diff/review/revert；二进制回滚见 `docs/rollback.md`（MCP 进程刷新条件与版本感知）。

## 9. 故障排查（摘自 docs/troubleshooting.md 主题）

| 症状 | 方向 |
|------|------|
| MCP 身份存疑 | 磁盘字节不能证明运行身份；服务器自报 `service_binary_replaced_on_disk` |
| stdio 断连 | stdout 被日志污染（协议流被毒化）——升级/回退二进制 |
| 写入被拒 | 多为 CAS 冲突（`write_conflict`）：源文件在读取后变了，按 Hint 重取再写 |
| 命令被"pending gate"拦截 | 有未完成事务回执；按提示跑对应 `status / resume / rollback` |
| 重命名目录后停在 `orphan_remove_candidates` | 正常护栏；待排除项未激活前不算孤儿 |
| 中文 JSON 在 PowerShell 5 下乱码 | 二进制已做 ASCII 安全转换；确认没有旧版本 |

## 10. 升级与卸载

- **升级**：`docs/upgrading.md`——验证新工件 → 替换二进制 → MCP 进程刷新（宿主可重载并证明替代进程时不必整机重启）→ 迁移路径按版本轴；进行中的审批对要先完成或丢弃再换二进制；
- **卸载**：`docs/uninstall.md`——移除二进制、宿主集成、（可选）仓库内 AOCI 资产；
- **发布件验证**：`docs/supply-chain.md` + `docs/install.md`（sha256sum -c / cosign verify-blob / gh attestation verify）。

## 11. 隐私与数据边界

- 本地优先：唯一对外连接是声明的数据库（目录元数据）与自身回环状态页；不联网、不上传；
- 凭据只按环境变量名引用，从不落盘；
- 索引文本由你自己的智能体经你已有的模型通道写出，AOCI 不新增数据出口；
- CI 可用性：可以在 CI 里跑 verify/check（见 FAQ），但全绿只证明治理一致性，不证明语义正确。
